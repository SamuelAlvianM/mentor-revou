# mentor-revou Agent Guide

Portfolio site for Samuel Alvian. `frontend/` is a Next.js 16 App Router + TypeScript + Tailwind v4 app; `backend/` is Flask + Flask-SQLAlchemy with SQLite; `scripts/` captures and optimises project screenshots.

## Repository layout

- `frontend/src/app/`: routes and layouts, including `/learning`.
- `frontend/src/components/`: client UI components; `frontend/src/lib/`: API helpers and shared data types.
- `frontend/public/`: logos, photos, and screenshots.
- `backend/app.py`: Flask app factory and API routes.
- `backend/models.py`: SQLAlchemy models and JSON serialization.
- `backend/seed.py`: destructive database reset and content seed.
- `backend/projects_data.py`: project content consumed by the seed.
- `deploy/`: PM2 configuration and SSH/Cloudflare deployment script.

## Dev environment

Backend setup, from repository root:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python seed.py
.\.venv\Scripts\python app.py
```

Frontend setup, in a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Development servers: Flask `http://127.0.0.1:5000`; Next.js `http://localhost:3000`. `API_URL` defaults to `http://127.0.0.1:5000` and controls Next rewrites to Flask. `backend/.env.example` documents `PORT`, `CORS_ORIGINS`, and optional `DATABASE_URL`.

`dev.ps1` starts both servers in separate PowerShell windows after dependencies and database setup exist.

## Build, lint, and checks

Run frontend commands from `frontend/`:

```powershell
npm run lint
npm run build
npm run start
```

`npm run lint` invokes `eslint`; `npm run build` creates the standalone Next output used by deployment. No test script, test directory, pytest configuration, or CI workflow is present in this repository.

Refresh screenshots with the commands documented in `README.md`:

```powershell
powershell -File scripts\capture-shots.ps1 -Out .\raw
backend\.venv\Scripts\python scripts\make_shots.py .\raw
```

## Conventions

- Keep route/page files thin. Frontend data access goes through typed helpers in `frontend/src/lib/api.ts`; `@/*` maps to `frontend/src/*`.
- Components and TypeScript files use lowercase-kebab-case names, for example `frontend/src/components/case-overlay.tsx`.
- Next pages that depend on Flask data use `dynamic = "force-dynamic"`; API fetches use `cache: "no-store"`.
- Server-side components fetch data; interactive components begin with `"use client"` and use React hooks.
- TypeScript uses strict mode, no emitted JS, bundler module resolution, and double-quoted strings with semicolons.
- Backend routes live in `backend/app.py`; persistence uses SQLAlchemy models in `backend/models.py`. JSON fields on `Project` are stored as JSON strings and decoded in `to_dict()`.
- API routes use `/api/health`, `/api/projects`, `/api/projects/<slug>`, `/api/profile`, and `/api/contact`. Contact input is stripped and length/email validated before insert.
- Content order and seed data live in `backend/seed.py` and `backend/projects_data.py`, not in frontend components.
- CSS uses Tailwind utilities plus custom site classes and palette variables in `frontend/src/app/globals.css`.
- Graphify map lives in `graphify-out/`; run `graphify update .` after source changes and query it before broad code searches.

## Pitfalls

- Run frontend commands inside `frontend/`; root has no `package.json`.
- Run backend commands inside `backend/`; imports such as `from models import ...` assume that working directory.
- `python seed.py` runs `db.drop_all()` and deletes contact messages. Do not run it against a database whose messages must survive.
- `frontend/AGENTS.md` is generated by Next.js and contains version-specific guidance; keep it in sync with the installed Next.js toolchain.
- Do not hand-edit `frontend/.next/`, `frontend/node_modules/`, `backend/.venv/`, `backend/instance/mentor_revou.db`, `graphify-out/`, or screenshot output under `raw/`.
- Deployment builds locally with `API_URL="http://127.0.0.1:5010"` and sends `.next/standalone`; `deploy/deploy.sh --seed` also replaces database contents. Use deployment flags only with explicit approval.
